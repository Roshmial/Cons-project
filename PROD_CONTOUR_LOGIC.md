# Production contour logic

## Логическая схема запросов

1. Пользователь открывает UI на `95:8803`.
2. Frontend рендерит chat-first интерфейс и отправляет API-запросы в backend-контур `178:8791`.
3. Backend обрабатывает auth, chat, jobs, dashboard, memory/personalization и связанные runtime-пайплайны.
4. При специальных сценариях backend/контур может опираться на `8794` как на дополнительный runtime-слой.
5. Вне UI параллельно работает `TG-API` на 95: сбор Telegram-данных, auth-link flow, daily/weekly мониторинг и digest pipeline.

## Почему это один product contour

- Пользователь видит единый продуктовый интерфейс.
- Backend-логика и часть operational automation физически разнесены, но вместе обеспечивают один рабочий сервис.
- Потеря любой из этих частей делает восстановление неполным: без `8803` нет реального prod UI; без `8791` нет business logic; без `TG-API` пропадает связанная operational автоматизация.

## Почему эти документы лежат в Cons-project

- Чтобы при переносе, аудите или аварийном восстановлении не приходилось заново восстанавливать картину по кускам.
- Чтобы было явно видно, какие части относятся к 95, какие к 178 и как они логически связаны.
