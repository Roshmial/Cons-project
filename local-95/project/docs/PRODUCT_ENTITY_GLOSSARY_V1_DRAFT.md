# Product Entity Glossary v1 Draft — Hermes

Дата: 2026-06-24
Статус: draft
Назначение: словарь продуктовых сущностей для Sprint 0

## 1. Зачем нужен словарь

Этот словарь нужен, чтобы одна и та же вещь не называлась по-разному в backend, frontend, документах и в голове пользователя.

Главная задача:
развести базовые рабочие сущности, чтобы продукт перестал ощущаться как смесь чата, файлов, задач и экспортов без границ.

## 2. Сущности

### Chat
Определение:
- место постановки задачи, уточнений и получения промежуточных ответов.

Пользователь видит:
- список чатов;
- конкретный диалог;
- сообщения;
- действия вокруг разговора.

Для чего нужен:
- задать запрос;
- уточнить запрос;
- увидеть ответ;
- перейти к следующему рабочему действию.

Чем не является:
- не файл;
- не recurring entity;
- не итоговый артефакт сам по себе;
- не подтверждённый handoff.

Допустимые действия:
- написать;
- продолжить;
- переименовать;
- архивировать;
- использовать как точку перехода в artifact / job / handoff.

### File
Определение:
- входной или выходной файловый объект, который можно использовать в работе.

Пользователь видит:
- файл в сообщении;
- файл в профиле;
- файл как результат генерации;
- действия открытия/скачивания/предпросмотра.

Для чего нужен:
- дать системе входной материал;
- сохранить и переиспользовать контекст;
- получить deliverable как файл.

Чем не является:
- не всякий файл является самостоятельным артефактом;
- не равен сообщению;
- не равен job.

Важное разделение:
- input file — пользовательский вход;
- generated file — созданный системой результат.

Допустимые действия:
- загрузить;
- выбрать из профиля;
- просмотреть;
- скачать;
- использовать в задаче.

### Artifact
Определение:
- самостоятельный рабочий результат, который можно использовать, передать, сохранить или читать отдельно от чата.

Пользователь видит:
- экспортируемый или открываемый результат;
- самостоятельный итог работы системы;
- документоподобный deliverable.

Для чего нужен:
- превратить ответ в рабочий объект;
- отдать результат дальше;
- сохранить итог не только как сообщение.

Чем не является:
- не любой assistant answer автоматически artifact;
- не любой файл является artifact;
- не recurring entity.

Допустимые действия:
- открыть;
- скачать;
- сохранить;
- передать дальше.

### Job
Определение:
- повторяемая задача, которую можно запускать вручную или по расписанию.

Пользователь видит:
- список задач;
- карточку задачи;
- schedule;
- подписки;
- историю запусков.

Для чего нужен:
- recurring automation;
- monitoring;
- digest;
- audit;
- periodic delivery.

Чем не является:
- не единичный run;
- не просто сообщение в чате;
- не результат сам по себе.

Допустимые действия:
- создать;
- изменить;
- запустить;
- приостановить;
- возобновить;
- подписаться на результат.

### Run
Определение:
- конкретное исполнение job.

Пользователь видит:
- историю запусков;
- статус конкретного исполнения;
- результат или ошибку конкретного запуска.

Для чего нужен:
- понять, что произошло в конкретный раз;
- увидеть success / error / degraded / empty_result;
- анализировать стабильность recurring-сценариев.

Чем не является:
- не сама recurring-задача;
- не общий чат-результат.

Допустимые действия:
- открыть;
- посмотреть статус;
- изучить результат;
- понять причину ошибки.

### Handoff
Определение:
- передача результата или заготовки результата в следующий рабочий контур.

Пользователь видит:
- не обязательно как отдельный экран, но как понятное следующее действие или зафиксированный статус передачи.

Для чего нужен:
- вывести результат из чата в дальнейший процесс;
- связать assistant/file/artifact с рабочим продолжением.

Чем не является:
- не просто фраза «можно использовать дальше»;
- не считается выполненным без явного подтверждения формата/направления передачи.

Допустимые действия:
- подготовить к передаче;
- оформить результат;
- направить в следующий контур.

### Policy / Admin layer
Определение:
- слой правил, наблюдаемости, справочников, управления пользователями и operational governance.

Пользователь видит:
- admin-разделы;
- health;
- events;
- users;
- reference data;
- operational settings.

Для чего нужен:
- управлять средой продукта;
- держать качество и повторяемость;
- контролировать runtime-состояние.

Чем не является:
- не основным пользовательским рабочим пространством;
- не заменой recurring core.

## 3. Ключевые различия, которые должны быть видны в UX

1. Chat != Artifact
Чат — место взаимодействия.
Artifact — самостоятельный результат.

2. File != Artifact
Файл может быть просто входом.
Artifact — это смысловой deliverable.

3. Job != Run
Job — повторяемая сущность.
Run — один конкретный запуск.

4. Answer != Handoff
Ответ в чате ещё не означает, что результат передан дальше.

5. Generated file != Input file
Сгенерированный результат и пользовательский вход нельзя путать в UI и терминологии.

## 4. Минимальные термины для UI и docs

Рекомендуемые базовые названия:
- Чат
- Файл
- Артефакт
- Задача
- Запуск
- Передача дальше
- Результат
- История запусков

Нежелательно смешивать без нужды:
- ответ / результат / файл / экспорт / артефакт;
- задача / запуск;
- передача / просто сохранение.
